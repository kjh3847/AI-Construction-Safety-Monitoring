# 2026-10-27 작업 기록 및 다음 수업 재개

## 확인된 상태

- EC2 Ubuntu에 계정 API, Python 가상환경, Nginx 설치.
- EC2에서 RDS PostgreSQL `safety` 데이터베이스 연결 성공.
- 서버의 `.env`에 DB 및 Brevo 설정 저장. 비밀번호/API 키는 저장소에 포함하지 않음.
- `safety-api.service`로 계정 API 실행. 코드 위치: `/home/ubuntu/safety-api`.
- DuckDNS 주소: `safety-capstone-2026.duckdns.org`.
- Certbot으로 Nginx HTTPS 적용 및 자동 갱신 예약. 발급 당시 만료일: 2027-01-25.
- HTTPS `/health` 응답 `{"status":"ok"}` 확인.
- CloudFront VPC 오리진은 만들었으나 배포(distribution)는 생성하지 않았음. 현재 연결은 DuckDNS → Nginx → 계정 API.

## 다음 수업 순서

1. 학교 실습 환경을 켜고 EC2와 RDS가 실행 상태인지 확인한다. 중지 후 재시작이면 설치를 반복하지 않는다.
2. EC2의 **현재 퍼블릭 IPv4**를 확인한다. 이전 값은 `43.201.29.166`이었지만 재시작하면 바뀔 수 있다.
3. DuckDNS의 해당 도메인 `current ip`를 현재 EC2 IP로 변경한다.
4. EC2 터미널에서 아래를 실행한다.

```bash
cd ~/safety-api
sudo systemctl status safety-api nginx --no-pager
curl -fsS --max-time 10 https://safety-capstone-2026.duckdns.org/health
```

`{"status":"ok"}`가 나오면 서버 연결이 복구된 것이다. API가 멈췄다면 `sudo systemctl restart safety-api` 후 `sudo journalctl -u safety-api -n 50 --no-pager`로 원인을 확인한다. 설정 파일이나 로그를 공유할 때 비밀번호/API 키는 가린다.

5. 로컬 프로젝트에서 `npm run dev` 실행 후 `http://localhost:5173`을 연다. Vite는 계정 요청을 HTTPS 계정 서버로 프록시한다.
6. 시스템 계정으로 로그인하고 관리자 계정 생성 → Brevo 메일 수신 → 임시 비밀번호 로그인 → 비밀번호 변경 → 로그아웃/재로그인을 실제로 확인한다.
7. 관리자 GUI에서도 같은 서버 주소로 로그인 및 계정 목록/생성/비활성화 흐름을 확인한다.

## 아직 남은 작업

- DuckDNS IP 자동 갱신 설정 및 EC2 재시작 후 검증.
- `sudo certbot renew --dry-run`으로 인증서 갱신 검증.
- 로그인부터 메일 수신/비밀번호 변경까지 전체 흐름 검증.
- 계정 API와 별도인 로컬 영상 서버의 DB/세션 설정 점검.
- 다른 PC 또는 정적 웹 배포에서는 Vite 개발 프록시가 없으므로 별도의 API 프록시/배포 설정 필요.
- 사용하지 않는 CloudFront VPC 오리진은 학교 정책에 맞춰 정리 여부 확인.

EC2/RDS는 학교 제공 자원을 사용한다. 새 유료 서비스나 요금제는 선택하지 않는다. 로컬 소스와 개발 서버는 계속 개발/영상 기능에 필요하므로 삭제하지 않는다.
